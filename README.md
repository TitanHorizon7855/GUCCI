# GUCCI — پنل 3x-ui سنایی (v3.4.2) روی Railway

پنل **3x-ui (MHSanaei/Sanaei) نسخه v3.4.2** + nginx reverse proxy با معماری تک‌پورت:

- ✅ پنل روی `https://دامنه/gucci/`
- ✅ سابسکریپشن داینامیک `https://دامنه/sub/{subId}` (لینک اشتباه → صفحه سیاه)
- ✅ **اینباند نامحدود**: `/in1..in50` (قابل افزایش) هر کدام یک پورت داخلی مجزا
- ✅ **TCP Proxy + Reality** برای اینباند TCP خام (پورت 9090)
- ✅ مسیریابی دامنه اختصاصی `HOST_ROUTES`
- ✅ استتار کامل: ریشه دامنه صفحه سیاه
- ✅ `RESET_DB=1` برای شروع از صفر

> نسخه s-ui هم در تاریخچه گیت موجود است.

---

## معماری و پورت‌ها

| سرویس | پورت داخلی | دسترسی عمومی |
|---|---|---|
| پنل 3x-ui | 2053 | فقط `https://دامنه/gucci/` |
| سابسکریپشن | 443 (loopback) | `https://دامنه/sub/{subId}` |
| اینباند اصلی VLESS/WS | 8080 | `https://دامنه/هرمسیر` (مثلاً `/cdn`) |
| اینباندهای اضافه | 8081..8130 | `https://دامنه/in1` تا `/in50` |
| اینباند TCP خام (Reality) | 9090 | Railway TCP Proxy |

فرمول: `/inN` ↔ پورت `8080 + N` — تعداد با `INBOUND_COUNT`.

## دیپلوی

1. Railway → New Project → Deploy from GitHub repo
2. Networking → Generate Domain
3. Volume به مسیر `/etc/x-ui/`
4. (برای اینباند Reality) Networking → TCP Proxy → پورت داخلی `9090`
5. پنل: `https://دامنه/gucci/` — admin/admin → **فوراً عوض کنید**

## کانفیگ اصلی (تمام نت‌ها — مسیر 443)

در پنل Inbound بسازید: Protocol=**VLESS**، پورت `8080` (یا `8080+N` برای `/inN`)، Network=**ws**، TLS=none، Path دلخواه.

لینک کلاینت (فقط دامنه + 443):
```
vless://UUID@دامنه.up.railway.app:443?encryption=none&security=tls&sni=دامنه.up.railway.app&fp=chrome&type=ws&host=دامنه.up.railway.app&path=%2Fcdn#GUCCI
```

## کانفیگ TCP Proxy + Reality (تحریم‌گریز)

اینbاند: Protocol=VLESS، پورت **9090**، Security=**reality**، SNI/Dest یکی از دامنه‌های معتبر زیر، fp=chrome:

```
www.microsoft.com  www.apple.com  aws.amazon.com  www.bing.com
azure.microsoft.com  go.microsoft.com  cdn-dynmedia-1.microsoft.com
```

لینک کلاینت با آدرس TCP Proxy:
```
vless://UUID@آدرس.proxy.rlwy.net:پورت?encryption=none&security=reality&sni=www.microsoft.com&fp=chrome&pbk=PUBLIC_KEY&sid=SHORT_ID&type=tcp#Reality
```

Reality روی TCP Proxy کار می‌کند چون TLS در لبه Railway terminate نمی‌شود؛ ترافیک از بیرون دقیقاً مثل handshake واقعی با مایکروسافت/اپل دیده می‌شود.

### استخر TCP Proxy (حداکثر ۳ تا در هر سرویس روی پلن Hobby)

Railway روی پلن فعلی حداکثر ۳ TCP Proxy در هر سرویس می‌دهد. هر proxy به یک پورت داخلی مجزا وصل می‌شود؛ در پنل روی همان پورت‌ها اینباند بسازید:

| آدرس عمومی | پورت داخلی اینباند |
|---|---|
| proxy#1 (دامنه+پورت خودش) | پورت دلخواه شما |
| proxy#2 | پورت دلخواه شما |
| proxy#3 | پورت دلخواه شما |

برای TCP Proxy بیشتر: سرویس Railway جداگانه (هر سرویس ۳ تای دیگر) یا ارتقای پلن.

> همان اینباند 9090 را می‌توانید هم‌زمان با آدرس دامنه پنل هم استفاده کنید اگر پشت Cloudflare باشید (پورت 443) — بخش HOST_ROUTES را ببینید.

## HOST_ROUTES — دامنه اختصاصی (پیشنهاد برای حداکثر اتصال از ایران)

اگر دامنه شخصی دارید و روی **Cloudflare** (ابر نارنجی) می‌گذارید، کلاینت به IPهای تمیز و anycast کلودفلر وصل می‌شود که از همه نت‌های ایران (ایرانسل/همراه‌اول/رایتل/شاتل/فیبر) قابل دسترس‌تر است:

1. دامنه را در Railway به‌عنوان Custom Domain اضافه کنید
2. `HOST_ROUTES=one.example.com:8081` بگذارید
3. اینباند را روی پورت متناظر بسازید

## ⚖️ ضریب مصرف ترافیک (Traffic Ratio)

وقتی بعضی مسیرها (مثلاً تونل ایران) گران‌تر از بقیه‌اند، می‌توانی مصرف هر کاربر را با ضریب حساب کنی — مثلاً هر ۱ گیگ مصرف واقعی، ۲ گیگ از سهمیه‌اش کم شود.

### نحوه استفاده (خیلی ساده)
1. توی پنل → کاربر می‌خوای → ویرایش
2. داخل فیلد **Comment** بنویس:
   - `ضریب:2` ← مصرف دو برابر حساب می‌شود
   - `ضریب:0.5` ← نصف حساب می‌شود (مثلاً مسیر جایزه)
   - `ratio=2` (انگلیسی هم قبوله)
3. ذخیره — تمام! هر ۴۵ ثانیه خودش اعمال می‌شود.

### داشبورد زنده
روی `https://{دامنه}/ratio/` جدول زنده‌ی همه‌ی کاربرها رو می‌بینی:
ضریب • مصرف واقعی • مصرف حساب‌شده • سهمیه • وضعیت

ورودش با `RATIO_USER` و `RATIO_PASS` (متغیرهای محیطی) — **حتماً RATIO_PASS رو عوض کن**.

### نکته‌های فنی
- بدون دست‌کاری در باینری x-ui: فقط با SQLite کار می‌کنه (آپدیت‌های x-ui رو نمی‌شکنه)
- فقط مصرفِ «از این لحظه به بعد» ضرب می‌شه، گذشته دست‌نخورده می‌مونه
- ریست دستی/خودکار مصرف کاربر تشخیص داده می‌شه و گیر نمی‌افته

## متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `INBOUND_COUNT` | `50` | تعداد `/in1..inN` |
| `INBOUND_BASE_PORT` | `8080` | پورت پایه |
| `TCP_INBOUND_PORT` | `9090` | پورت اینباند TCP خام |
| `HOST_ROUTES` | خالی | `host:port,...` |
| `RESET_DB` | خالی | `1` = wipe کامل دیتابیس (بعداً حذف کنید!) |
| `RATIO_USER` | `gucci` | یوزر داشبورد ضریب |
| `RATIO_PASS` | `gucci` | رمز داشبورد ضریب ⚠️ عوضش کن |
| `RATIO_INTERVAL` | `45` | بازه‌ی اعمال ضریب (ثانیه) |

## صداقت فنی درباره «هرگز فیلتر نمی‌شود»

هیچ راه‌حل تضمینی ۱۰۰٪ وجود ندارد — فیلترینگ پویاست. این پروژه احتمال شناسایی را به حداقل می‌رساند:
- همه‌چیز روی 443/TLS با ظاهر HTTPS عادی + `fp=chrome`
- Reality با SNI دامنه‌های معتبر جهانی
- پنل و ساب مخفی (صفحه سیاه)
- ۵۰ مسیر جایگزین برای چرخش سریع
اگر مسیری بسته شد: مسیر ws را عوض کنید، `/inN` دیگر بزنید، یا Reality را فعال کنید. برای حداکثر پایداری از ایران، دامنه پشت Cloudflare (HOST_ROUTES) مؤثرترین گزینه است.
